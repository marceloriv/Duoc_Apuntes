## GitHub Actions + GitHub Pages + Terraform

Un mismo proyecto puede usar **GitHub Actions + GitHub Pages + Terraform**, pero cada uno cumple una función diferente.

>[!summary]
>Resumen de piezas:
>
> - **GitHub** → guarda el código.
> - **GitHub Actions** → automatiza test, build y deploy ante un evento (ej. `git push`).
> - **GitHub Pages** → publica una página web estática (frontend/documentación).
> - **Terraform** → administra la infraestructura en AWS (VPC, EC2, RDS, S3).

Piensa en ellos como piezas distintas:

```text
                    PROYECTO
                       │
                       ▼
                  GitHub Repo
                       │
             ┌─────────┴─────────┐
             │                   │
             ▼                   ▼
      GitHub Actions          Terraform
             │                   │
             │                   ▼
             │                  AWS
             │             ┌─────┼─────┐
             │             │     │     │
             │            EC2   RDS   S3
             │
             ▼
       GitHub Pages
             │
             ▼
        Sitio web
```

### ¿Qué hace cada uno?

**GitHub**
Guarda el código:

```text
mi-proyecto/
├── src/
├── terraform/
├── package.json
└── .github/
    └── workflows/
```

**GitHub Actions**
Automatiza cosas cuando ocurre un evento, por ejemplo un `git push`:

```text
push
  ↓
GitHub Actions
  ↓
test
  ↓
build
  ↓
deploy
```

**GitHub Pages**
Sirve para publicar una página web estática. Por ejemplo:

```text
React / HTML / CSS / JS
          ↓
    GitHub Actions
          ↓
    GitHub Pages
```

**Terraform**
Administra infraestructura. Por ejemplo:

```text
Terraform
   ↓
AWS
├── VPC
├── EC2
├── RDS
├── S3
└── Load Balancer
```

---

### Y pueden trabajar juntos

Por ejemplo, imagina que tienes una aplicación:

```text
                    GitHub
                       │
                  git push
                       │
                       ▼
                GitHub Actions
                   /        \
                  /          \
                 ▼            ▼
          GitHub Pages     Terraform
              │                │
              ▼                ▼
          Frontend             AWS
                             ┌───────┐
                             │  EC2  │
                             │  RDS  │
                             │  S3   │
                             └───────┘
```

Podrías tener:

* **GitHub Pages** → frontend/documentación.
* **AWS** → backend, base de datos, almacenamiento, etc.
* **Terraform** → crea y administra los recursos AWS.
* **GitHub Actions** → automáticamente ejecuta los builds, tests y Terraform.

### Incluso puedes hacer algo más interesante

Por ejemplo:

```text
git push
   │
   ▼
GitHub Actions
   │
   ├── 1. Test
   │
   ├── 2. Build frontend
   │
   ├── 3. Deploy → GitHub Pages
   │
   └── 4. Terraform
           │
           ├── plan
           │
           └── apply
                 │
                 ▼
                AWS
```

Así tienes un proyecto donde **un `git push` puede desencadenar prácticamente todo el despliegue**.

Y si estás pensando en **réplicas/DR en AWS**, Terraform puede describir la infraestructura de producción y la infraestructura de respaldo, mientras que GitHub Actions puede automatizar cuándo y cómo se despliega esa configuración.
