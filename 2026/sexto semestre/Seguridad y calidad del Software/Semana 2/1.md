## Pruebas de software

La seguridad y calidad del software abarcan dos grandes categorías de pruebas:

- **Funcionales**
- **No funcionales**

Ambas dimensiones son críticas para el producto final.

### Funcionales

> [!IMPORTANT]
> **¿El software cumple con las funciones especificadas?**

Las pruebas funcionales verifican que el sistema ejecute lo definido en la especificación de requisitos y documentación del proyecto.

### No funcionales

> [!IMPORTANT]
> **¿El software se comporta de manera correcta, rápida y segura?**

Tipos de pruebas no funcionales abordadas:

1. **Rendimiento**: mide tiempos de respuesta, latencia y uso de recursos bajo condiciones normales. A veces mejorar el rendimiento requiere optimizaciones a nivel de stack o lenguaje.
2. **Carga**: evalúa el comportamiento bajo alta demanda. En infraestructura *on-premise* antigua suele ser un cuello de botella frecuente; en la nube se mitiga con escalamiento horizontal/vertical.
3. **Seguridad**: evalúa controles de acceso, vulnerabilidades y brechas derivadas de una mala implementación de roles (RBAC).
4. **Usabilidad**: detecta fricciones de UI/UX. Incluye inconsistencias de diseño percibidas por el usuario según su dispositivo o pantalla.

> [!NOTE]
> El código de color (hex/RGB) es constante en el código, pero puede percibirse distinto según la calibración del monitor del cliente.

## Usuarios y entornos

### Tipos de usuarios

- **Usuario final**: quien utiliza el producto diariamente. Conviene involucrarlo desde etapas tempranas para mapear sus patrones reales de uso.
- **Usuario de prueba (QA)**: interno o externo, enfocado en validar casos límite y reportar bugs.
- **Usuario administrador**: usuario con rol privilegiado para gestión del sistema.

### Entornos

- **Entorno de desarrollo**: pruebas internas y construcción activa.
- **Entorno de producción**: sistema en vivo con usuarios reales y datos productivos.

## Lenguajes y consideraciones técnicas

- **Rust**:
  - Garantiza seguridad de memoria en tiempo de compilación sin recolector de basura (garbage collector).
  - Usado para reemplazar módulos críticos de Python o JavaScript cuando se requiere máximo desempeño.
- **Go (Golang)**:
  - Compilado, concurrencia nativa mediante *goroutines*, eficiente para microservicios y backend.
- **MicroPython**:
  - Implementación optimizada de Python 3 diseñada para microcontroladores y dispositivos embebidos.

## Validación de datos (ejemplo bancario)

Datos habituales de una transferencia:

- Nombre
- **RUT**
- Banco
- Tipo de cuenta
- **N° de cuenta**
- Correo electrónico

Actualmente muchas plataformas bancarias validan preliminarmente el formato del **RUT** y la estructura del **N° de cuenta** mediante algoritmos de dígito verificador y reglas de negocio de la entidad.

## Cosas a tomar en cuenta

- **Design Thinking**:
  - Muchos problemas de calidad y aceptación nacen de no entender las necesidades reales del usuario antes de diseñar e implementar la solución.
